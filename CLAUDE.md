# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SI-studio: split a neural network across edge and cloud machines, run it, and
chart what happened. Two halves:

- **`split-inference-pipeline.html`** — the entire frontend UI (React) in one
  self-contained file. This is the **source of truth** for the UI and is
  **never edited by the build** — it is unpacked and patched on the way to
  `backend/web/`. Edit it directly when changing UI behavior.
- **`backend/`** — a FastAPI control plane (`guide_code.md` is its spec) that
  serves the built site, fans SSH commands out to real edge/cloud machines,
  deploys model shards over SCP, runs split inference across RabbitMQ, and
  streams live metrics back over a WebSocket.

Everything under `backend/` is the actual codebase Claude will usually touch.
`backend/README.md` is extremely detailed (API table, security model, metrics
payload shape, auto-measure algorithm) — read it before making non-trivial
backend changes rather than re-deriving behavior from source.

## Commands

All commands run from `backend/`.

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env                                # set API_TOKEN at minimum
python tools/build_web.py                           # REQUIRED before serving — unpacks the HTML bundle into web/
uvicorn app.main:app --reload
```

```bash
python tools/build_web.py --check     # non-zero exit if the HTML bundle changed since last build — CI-worthy check
```

Tests:

```bash
pip install pytest httpx numpy quickjs   # quickjs is optional: runs ui/live-patch.js in a real JS engine
pytest -q                                 # hermetic — no broker, no network needed
pytest tests/test_broker_integration.py   # +7 tests, needs a real RabbitMQ (else skipped)
pytest tests/test_simulation.py -q        # simulator-parity tests specifically
pytest tests/test_foo.py::test_bar -q     # single test
```

Health check once running: `curl localhost:8000/health`.

Model shards (needed before a live run, not needed for Simulate mode or for
hermetic tests):

```bash
python tools/split_model.py --weights yolo11n.pt --list-cuts   # which cuts are valid
python tools/split_model.py --weights yolo11n.pt --cut 6       # writes head.pt/tail.pt into shards/
```

## Architecture

### The UI build is a patch pipeline, not a compiler

`split-inference-pipeline.html` ships as a self-extracting bundle: the page is
a JSON string inside `<script type="__bundler/template">`, assets are base64,
and the Control tab's handlers are `setTimeout` mocks. `tools/build_web.py`:

1. Unpacks that bundle into `backend/web/` (`index.html`, `vendor/*.js`,
   `assets/*`).
2. Applies fixed patches by finding known anchors in the unpacked JS: a header
   group (Live toggle, connection chip, Deploy), a Connect button in the
   per-device settings form, a **⟳ measure** button per stage, and appends
   [`ui/live-patch.js`](backend/ui/live-patch.js), which overrides
   `Component.prototype` methods (`simCluster`, `sshRun`, `sshScp`,
   `sshConnectAll`, `sshServerTest`, `runFlow`) rather than rewriting them.

If an anchor moves (i.e. the HTML was re-exported from the design tool in an
incompatible way), **the build fails loudly** instead of silently shipping a
site with a dead toggle. This is deliberate — don't work around a build
failure by patching `web/` directly; fix the anchor/patch in
`tools/build_web.py` or `ui/live-patch.js`.

`web/` is generated and gitignored. Never hand-edit it.

### Simulate vs Live

A single header toggle decides where numbers come from — same UI either way:

- **Simulate**: math runs in the browser (`app/inference/simulation.py` is a
  byte-for-byte Python port of that same JS math, verified against
  `tests/golden_ui_math.tsv` — a golden file generated by running the
  original JS in an independent engine). Touch `simulation.py` only alongside
  re-running that harness if the UI's formulas changed.
- **Live**: talks to real machines over SSH (`app/ssh/`) and RabbitMQ
  (`app/inference/broker.py`, `app/inference/orchestrator.py`).
- **Control tab is the exception** — it always talks to real machines
  regardless of the toggle.

### The control server is a synthetic target, not a device row

The machine you SSH into (and optionally the jump host devices sit behind) is
addressable as target id `__server__`, resolved from `ServerConfig` at
request time in `app/ssh/gateway.py` — it is deliberately **not** a row in
the `device` table, because a phantom device would be picked up by
`build_clusters()` / `topology.py` and skew every simulated metric.
`ServerConfig.SSH_SECRET_REF` must equal `gateway.SERVER_DEVICE_ID`
(asserted at import time) so its password resolves through the same secret
store path as a real device's.

With `jump_enabled`, every device connection tunnels through the server's own
SSH connection (asyncssh `tunnel=`, i.e. `ProxyJump`) — the usual lab shape of
one routable control machine with edge/cloud nodes on a private network
behind it.

### Command execution model (`app/ssh/commands.py`)

`POST /control/exec` is not a simple request/response: commands run under a
pty (so long-running Python scripts aren't block-buffered), the HTTP call
returns as soon as the command finishes **or** after `EXEC_DETACH_AFTER`
seconds — whichever is first — and anything still running is reported in
`running` while continuing to stream as `exec_line` WebSocket frames. Stop a
detached command with `POST /control/exec/stop` (SIGINT via `\x03` in the pty
→ SIGTERM → channel close).

Security guard lives at the **router boundary**, not inside `run_command`
itself — the orchestrator's own internal calls legitimately need shell
redirects/`&` for `nohup … &`, so validation only applies to operator input
entering through the API. The guard is an allow-list of prefixes plus a
quote-aware shell-metacharacter scan; `ALLOW_UNSAFE_COMMANDS=true` disables
both and should only be set when every device in the inventory is trusted.
Destructive commands (`sudo reboot`, `shutdown`, `systemctl stop/restart
inference-agent`) need `confirm: true` and are always written to
`AuditLog` regardless of outcome.

### Metrics pipeline

Cloud agents publish one JSON report per frame to `metrics_queue`. The
orchestrator keeps a rolling window (`METRICS_WINDOW` frames) per cluster and
broadcasts an aggregated payload at `METRICS_BROADCAST_HZ` over
`/ws/stream` — see `backend/README.md`'s "Metric collection" and "Metrics
payload" sections for the exact field semantics (`fps` from arrival
timestamps not `e2e_ms`, `*_util` as mean over the pipeline bottleneck, etc.)
before changing aggregation logic.

### Reports are folders, not database rows

`POST /reports/analyze` walks a result directory over SFTP (text/CSV/JSON,
bounded to 400 files / 256 MB / 8 levels), infers a chart form per metric
from the data's shape (trend / comparison / distribution / stat tile), and
writes a self-contained folder under `backend/reports/<day-time>_<case>/`
(`manifest.json` + `imgs/*.png`). Charting logic
(`app/reports/charts.py`, `app/reports/palette.py`) follows
`guides/visual_guide.md` — that guide is the spec for chart form/color rules,
`tests/test_reports.py` pins the palette validator to the guide's own
numbers. Nothing is in SQLite here; copying the folder is the entire export
story, which is also why `logs/config.yaml` (containing a plaintext broker
password) must be redacted before sharing a report — see the `sed` one-liner
in the root `README.md`.

### Auto-run runs locally; everything else runs remotely

`app/services/autorun.py` is the one execution path that does **not** go over
SSH. It runs an operator-supplied bash script as a local subprocess on the
machine hosting this service — the lab server, where the project directories
live — because a script that drives a dozen projects in sequence is the
conductor of the fleet, not one of its members. Don't "fix" it to route through
`ssh/commands.py`.

Progress is read out of the script's stdout: explicit `::step::` /
`::step-done:: … rc=n` markers, falling back to `=== banner ===` heuristics that
switch off permanently once a real marker appears. The run-level verdict is
always the process's exit code, so it never depends on the script cooperating.

`::progress:: k=v` and `::note::` are deliberately different channels — the
first updates the **Progress** tab only, the second goes to Telegram. A run
polling FPS every 20 s for half an hour is ~80 messages if you conflate them.
Don't make progress notify.

A schedule inherits only `.env` keys matching `AUTORUN_ENV_PREFIXES` (default
`FLEET_`), because `pydantic-settings` loads `.env` into `Settings` and never
into the environment. Keep it an allow-list: `API_TOKEN` and
`TELEGRAM_BOT_TOKEN` must not reach a script that might `set -x` them into a
transcript this service stores and forwards.

`autorun/fleet-3project.sh` + `autorun/fleet.py` are the real schedule (split →
PA → dmsf on the 13-host fleet) and its paramiko SSH driver. Neither contains a
credential — that is what makes them committable, while `run/guides/*.md` and
`controller/` (which do) are gitignored. Never inline a fleet password into
`autorun/`.

Two invariants worth not breaking: the child is spawned in **its own process
group** (`start_new_session` / `CREATE_NEW_PROCESS_GROUP`) so stopping kills the
`python server.py` it launched rather than orphaning it; and a run going quiet
is *reported*, never killed — a training step is legitimately silent for a long
time, and killing it would destroy the run the feature exists to protect.

Notifications (`app/services/notify.py`, Telegram) use stdlib `urllib` on a
worker thread rather than adding an HTTP dependency, and swallow every failure:
a notifier that can crash the run it reports on is worse than no notifier. The
bot token never reaches a log line, an error string, or an API response.

### Auto-measuring device specs (`app/services/measure.py`)

Compute (`gflops`) and latency are measured across the whole fleet at once;
**bandwidth cannot be**, because devices share an uplink — so the bandwidth
phase runs strictly one device at a time for a `solo` figure, then optionally
(`contention: true`, default) a second pass with everything transferring
simultaneously for a `shared` figure. `bandwidth_basis` (default `shared`)
picks which one gets written to the device spec that feeds the simulator.
Don't change this to a per-device-parallel measurement — it would invalidate
exactly the number the split decision depends on.

### Secrets

Private keys in `SECRETS_DIR/<key_ref>.pem`; passwords/passphrases in
`SECRETS_DIR/credentials.json`, Fernet-encrypted, chmod 0600. No endpoint
ever returns a stored secret (`GET /devices` exposes only `has_password`).
`known_hosts=None` is intentional (lab devices' host keys churn) and trades
away MITM protection — appropriate on a trusted network only, including
through the jump host.

## Notes

- `controller/` (this working directory) holds operational scratch notes for
  reaching the real device fleet (`hosts.txt`, `dirs.txt`) — it is not part of
  the application source and has no build/test relationship to `backend/`.
  `hosts.txt` contains plaintext SSH passwords for lab machines; treat it like
  a secret, not like code.
- The frontend and Python simulator must stay in lockstep. If you touch either
  the UI's math or `app/inference/simulation.py`, re-run the golden-file
  harness described in `backend/README.md`'s "Parity with the UI simulator"
  section and refresh `tests/golden_ui_math.tsv`.
